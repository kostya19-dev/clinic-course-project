## Использованные запросы

Замеры выполнялись для четырех ключевых операций:
- получение расписания врача за период;
- получение истории пациента;
- получение списка счетов пациента;
- отчет по выручке врача за период.

## Результаты замеров

### 1. Расписание врача

При использовании индекса `idx_appointments_doctor_time`:
- план: `Index Scan`
- время выполнения: `0.055 ms`

При запрете индексных стратегий планировщика:
- план: `Seq Scan` + `Sort`
- время выполнения: `0.205 ms`

Вывод: индекс по `(doctor_id, starts_at, ends_at)` заметно сокращает стоимость поиска расписания даже на относительно небольшом наборе данных.

### 2. История пациента

При использовании индекса `idx_appointments_patient_history`:
- план: `Index Scan` по таблице `appointments` и индексные обращения к связанным таблицам
- время выполнения: `0.195 ms`

При запрете индексных стратегий:
- план: `Seq Scan` по `appointments`, `services`, `doctors`, `users` с `Hash Join`
- время выполнения: `1.314 ms`

Вывод: индекс по `(patient_id, starts_at DESC)` существенно уменьшает стоимость получения истории пациента и позволяет избежать полного просмотра таблиц.

### 3. Счета пациента

При использовании индекса `idx_invoices_patient_status`:
- план: `Index Scan`
- время выполнения: `0.071 ms`

При запрете индексных стратегий:
- план: `Seq Scan` + `Sort`
- время выполнения: `0.188 ms`

Вывод: индекс по `(patient_id, status, issued_at DESC)` ускоряет получение финансовой информации по пациенту и уменьшает число прочитанных страниц.

### 4. Отчет по выручке врача за период

Для агрегирующего отчета по всем завершенным приемам за период планировщик выбрал:
- `Seq Scan` по `appointments`
- `Seq Scan` по `visits`
- `Seq Scan` по `invoices`
- `Hash Join` и `HashAggregate`
- время выполнения: `4.265 ms`

Вывод: для широкого отчета, охватывающего значительную долю строк таблиц, последовательное сканирование оказалось оправданным. Это показывает, что индексы наиболее полезны для селективных запросов, а не для агрегирования почти всего набора данных.

## Общий вывод

Проведенное исследование подтверждает, что индексация критична для запросов расписания, истории пациента и списка счетов. Для широких аналитических отчетов влияние индексов существенно ниже, и планировщик PostgreSQL обоснованно предпочитает последовательное сканирование и хеш-агрегацию.
